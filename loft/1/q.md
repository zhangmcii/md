### **第1轮：项目理解与整体设计（意图与边界）**

1.  **架构决策：** 你选择了 **Flask (Python) + Vue 3** 作为技术栈。在处理社交平台这种高频交互、并发量潜在较大的场景时，Flask 的同步阻塞特性明显不如 Go 的协程或 Node.js 的异步 I/O。请问你当初为什么做出这个选择？如果是为了开发效率，那么当用户量达到 10w+ 时，你准备如何重构后端架构来解决性能天花板？
2.  **解耦设计：** 你的项目中既有传统的 RESTful API，又有基于 Socket.IO 的长连接。请详细说明你的后端是如何划分这两个模块的？如果即时通讯服务（IM）因为消息量过载而崩溃，是否会影响到用户的博客浏览和登录功能？
3.  **核心痛点：** 现有的开源博客或社交平台（如 WordPress, Typecho, 或者各种轻量级社交框架）已经非常成熟，你的项目解决了它们中哪一个“无法满足”的核心问题？或者说，这个项目的“灵魂功能”在技术实现上有何独特之处？

### **第2轮：技术深挖（并发与实时性）**

1.  **WebSocket 扩展性：** Flask 本身是 WSGI 协议，它是同步的。你在实现 Socket.IO 时，底层使用的是线程模式还是协程（如 Gevent/Eventlet）？如果现在有 5000 个用户同时在线保持长连接，你的服务器内存和 CPU 占用大概在什么水平？你如何监控并定位其中的死锁或资源泄露问题？
2.  **状态同步一致性：** 在社交场景下，如果 A 用户点赞了 B 用户的文章，此时 B 正在通过 WebSocket 聊天。你是如何保证点赞动态能即时、准确地推送到 B 的界面，同时保证数据库里的计数和前端显示的数字在网络波动时依然保持最终一致性？
3.  **身份校验的成本：** 你的项目使用了 JWT 和 OAuth。对于 WebSocket 连接，你是在握手阶段校验一次权限，还是在每次消息传输时都进行校验？如果是前者，如何处理 Token 在连接期间过期的情况？如果是后者，如何在高频通信中降低鉴权带来的性能损耗？

### **第3轮：数据建模与存储（深度与优化）**

1.  **关系模型性能：** 社交系统最核心的是“关系”（如：粉丝、关注、好友）。在你的数据库设计中，如果一个“大 V”拥有 100 万粉丝，当你查询他的粉丝列表或者判断某个用户是否是他的粉丝时，你的 SQL 语句是如何优化的？有没有考虑到深度分页带来的性能坍塌？
2.  **复杂嵌套处理：** 博客系统必然涉及“多级评论”或“嵌套回复”。你是采用递归查询（Recursive Query）、路径枚举（Path Enumeration）还是闭包表（Closure Table）来存储这种树形结构？请从查询效率和写入复杂度的角度对比说明你的选择理由。
3.  **索引失效场景：** 请列举你项目中搜索功能（如搜索文章标题或内容）的实现逻辑。在模糊匹配 `LIKE '%keyword%'` 的情况下，索引会失效，你当时是如何处理大文本搜索的？有没有考虑过引入全文检索引擎？

### **第4轮：系统设计能力（高可用与扩展）**

1.  **分布式环境下的长连接：** 如果当前的单台服务器承载不了用户量，我增加到 3 台服务器并使用 Nginx 做负载均衡。此时，连接在 Server A 的用户如何发消息给连接在 Server B 的用户？请给出你的分布式 Socket 方案（提示：涉及消息中间件）。
2.  **应对“热点”事件：** 假设你的 Loft 突然出现一个爆款文章，短时间内有数万次并发读请求。在不改变现有数据库架构的前提下，你会引入哪种缓存策略？如何解决缓存穿透和缓存击穿问题？
3.  **异步任务治理：** 诸如“发送注册邮件”、“图片压缩”、“消息通知推送”这些耗时操作，如果你依然放在请求响应循环（Request-Response Cycle）里处理，会严重拖慢用户体验。你是否设计了任务队列？如何保证任务在处理失败后的重试逻辑和幂等性？

### **第5轮：工程能力与进阶思考（批判性思维）**

1.  **代码腐化与重构：** 现在回看你的源代码，哪一个模块的设计让你觉得“当时写得太耦合了，现在很难维护”？如果让你把“即时聊天”模块彻底抽离成一个独立的微服务，你认为最大的技术障碍在哪里？
2.  **安全性防御：** 除了基础的 JWT，你如何防御针对社交平台的 XSS 攻击（尤其是在用户评论和个人简介处）？对于恶意的 API 爬虫，你有没有在后端实现频率限制（Rate Limiting）？
3.  **商业化考量：** 如果这个系统要正式商业化运行，且需要支持“万人同时在线聊天”，你认为目前代码中最大的性能“定时炸弹”在哪里？你会选择更换哪一部分的技术栈来彻底解决它？
