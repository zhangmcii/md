# 🛠️ API Batch Probe Paradigm | 第三方 API 批量调用工程范式

**治好 AI 的“大厂架构病”与“代码裸奔症”。**

这是一个专为 AI Agent（如 Cursor、Windsurf、Dify、GPTs 等）定制的 **系统提示词 / 技能卡（`skill.md`）**。它的核心目的，是规范 AI 在面对“批量调用第三方 API、跑离线评测集、多 Provider 横向对比、压测/打标”等需求时，如何在**工程质量**与**实现复杂度**之间做动态平衡。

---

## 🛑 为什么要用这个项目？

我们在让 AI 写批量出网脚本时，经常遇到两个极端：

1. **过度工程化（大厂架构病）**：只是跑 20 条数据验证一下，AI 却给你默写了一个包含 `providers/` 目录、抽象基类、注册表、Redis 队列、多级配置文件的“百万级高并发常驻服务”框架。
2. **鲁棒性裸奔（代码裸奔症）**：跑几万条长周期数据，AI 却写了个最简单的 `asyncio.gather`，不限流、无超时、对 4xx 错误疯狂重试导致被厂商封号，中途一崩溃数据全丢。

本项目的 `skill.md` 是给 AI 注入的**工程常识底座**。它逼迫 AI 在动笔前先判定复杂度等级（Level 0~2），**少即是多，按需动态启用防御性机制**。

---

## 🌟 核心设计：复杂度三级分层（Complexity Tiering）

| 级别 | 触发条件 | 核心启用机制 | 严禁引入的冗余 |
| --- | --- | --- | --- |
| **Level 0**<br>

<br>临时验证 | 任务数 < 50<br>

<br>跑一次就丢 | 简单并发、单请求超时、朴素重试、print 进度 | 严禁抽象类、断点续跑、目录拆分、多文件结构（控制在 200 行内） |
| **Level 1**<br>

<br>标准批跑 | 50 ~ 5000 条<br>

<br>大模型打标/评测 | 环境变量配置、**边跑边落 JSONL（即时刷盘）**、错误分类处理、dry-run 模式 | 仍不需要熔断、自适应并发、复杂 Tracing 机制 |
| **Level 2**<br>

<br>长跑/压测 | > 5000 条<br>

<br>跨天/高额计费/多端对比 | Shard 续跑、**自适应并发降级**、令牌桶限速、Graceful Shutdown、指标汇总 | 只有此层才允许考虑 Provider 抽象与多文件目录 |

## 🚀 如何使用？

你可以直接把本项目中的 `SKILL.md` 喂给你的 AI 开发助手。

### 在 Claude Code  中安装 (推荐)

将 `SKILL.md` 放入你项目的根目录，或者直接复制其内容添加到 `.claude/skills/third-party-api-batch-probe` 中：

安装后直接在 Claude Code 中用自然语言触发，不需要输入任何命令。

```text
当需要帮我编写任何涉及“批量调用接口”、“跑评测集”、“大模型打标”、"做竞品能力验证"的脚本时

```

## 📁 目录范式产物

遵循本范式的脚本运行后，会在 `output/` 和 `logs/` 下自动生成带**时间戳**的非覆盖式产物：

```text
.
├── logs/
│   └── run_20260521_153000.log       # 控制台+文件双向落盘日志，严禁 Rotation
├── output/
│   ├── result_20260521_153000.jsonl  # 核心防灾产物，保留 raw_response
│   └── summary_20260521_153000.csv   # 可选：面向业务的可视化宽表
├── .gitignore                        # 默认附带，自动拦截大文件与本地密钥
└── batch_probe.py                    # 纯巧、轻量、高鲁棒性的单文件脚本

```
